# 遊戲資源包

遊戲資源包放在這個資料夾，每個遊戲一個子資料夾，例如 `games/fogmap/`。遊戲在學員、工作人員的手機上執行，盡量在手機上算，只有需要時才把資料送回後端。資源包不用安裝，推到 GitHub Pages 就能用。

## 怎麼讓學員玩

1. 把資源包加進 `games/index.json` 的 `packs`，管理端「Package 管理」最下面的「遊戲資源包」就會列出來。
2. 管理端「營期流程與活動 → 遊戲資源包」：每個活動選一個資源包，填按鈕文字和這個活動的設定，然後按「儲存」。
3. 活動公開後，學員端、工作人員端的活動卡片點開會出現「🎮 開始遊戲」。活動卡片也可以自己放「開始遊戲」按鈕。
   - 學員要等活動公開才能玩。工作人員不受限制，可以先進去準備，例如產生關主密鑰。
   - 同一個資源包用在兩個活動時，進度和密鑰各自分開。
4. 學員、工作人員都要先在營隊互動 App 登入過，而且要用同一支手機、同一個瀏覽器。

遊戲頁網址：`game.html?c=營隊ID&g=資源包ID&a=活動ID&s=student|worker`

## 資料夾內容

| 檔案 | 說明 |
| --- | --- |
| `manifest.json` | 資源包說明與設定（必要） |
| `game.js` | 遊戲程式（必要），呼叫 `CampGame.register({ mount: function (el, host) { … } })` |
| `README.md` | 給籌辦團隊看的說明（必要）：怎麼玩、關主要做什麼、設定欄位、要準備什麼 |
| `game.css`、圖片、地圖、音效 | 選用。圖片等素材要列在 manifest 的 `files`，程式裡用 `host.asset('檔名')` 拿網址 |

`manifest.json`：

```json
{
  "id": "fogmap", "name": "霧之校園", "version": "0.1.0", "summary": "一句話說明",
  "entry": "game.js", "css": "game.css", "files": ["map.svg"],
  "data": { "遊戲的預設設定": "…" },
  "config": [
    { "key": "endAt", "label": "活動結束時間", "type": "datetime", "hint": "說明" },
    { "key": "squads", "label": "小隊數", "type": "number", "dflt": 8 }
  ]
}
```

## 關主登入

管理端「遊戲資源包」分頁每個活動可以設定：

- **關主登入**（預設打開）：工作人員端的活動卡片顯示「🎯 關主登入」，按了直接進遊戲的工作人員畫面。關掉就不顯示。
- **關主通行碼**（選填）：有設的話，工作人員第一次進關主要輸入，之後這支手機記得。改了通行碼要重新輸入。沒通過的人不能產生關主密鑰、不能上傳分數（伺服器會擋）。

從活動進來產生的關主密鑰會綁這個活動（測試模式是那次測試），別的活動或沒從活動產生的密鑰驗不過。遊戲不用自己處理，`host.sign`、`host.score` 會自動帶關主證明。

## 測試模式

管理端「營期流程與活動 → 遊戲資源包」每個連了遊戲的活動都有「🧪 開始測試模式」。測試中一切跟正式一樣：同步、送出、關主密鑰、上傳分數（會進排行榜，Game 名稱加「（測試）」），而且學員不用等活動公開就能從連結打開。按「結束測試並歸零」時，這次測試的遊戲收件、團隊計分的 Game 和分數全部刪掉；手機上的存檔、同步因為範圍換了，也一起歸零。正式的資料不受影響。

遊戲只要一律用 `host.ch()`、`host.scope`、`host.save()`，不用為測試模式寫任何程式。`host.activity.test` 可以拿來在畫面上提示。

## 下載到手機

學員或工作人員按活動卡片上的遊戲按鈕，會先看到下載畫面（圓環進度、正在下載哪個檔案，完成打勾），把 `entry`、`css` 和 `files` 列的檔案全部存進手機（瀏覽器的 Cache Storage），再進遊戲。之後再打開，版本一樣就不重新下載，進遊戲幾乎不用等，也比較不怕營地網路慢（登入確認、同步還是要有網路；送出斷網會先存著補送）。

改了資源包任何檔案，**一定要把 `version` 加一**（`index.json` 也一起改），手機才會知道要更新，會顯示「有新版本，更新中」。沒列在 `files` 的素材不會下載，`host.asset` 會改從網路拿。

`config` 是管理端每個活動可以改的欄位，type 可以用 text、number、datetime 或 textarea。活動填的值會蓋過 `data` 裡同名的預設值。

## 遊戲拿到的 host

遊戲只透過 `host` 和系統溝通，所以新增遊戲不用改核心程式。

| 用法 | 說明 |
| --- | --- |
| `host.me` | `{ kind: 'student'或'worker', name, squad, sid, wid }`，小隊以人員名單為準 |
| `host.data` | 設定，等於 manifest.data 加上這個活動的設定 |
| `host.activity`、`host.scope` | 從活動進來時是 `{ id, name, test }` 和資料範圍（平常是活動 ID；測試模式是「活動ID-t第幾次」） |
| `host.ch(name)` | 頻道名稱加上活動，讓不同活動的資料分開 |
| `host.now()`、`host.time(v)` | 伺服器時間（學員改手機時間沒有用）；把設定裡的時間轉成毫秒 |
| `host.sync(ch, o)` | 即時同步，用來互相看狀態。這是「盡量送到」，人多時會自動放慢 |
| `host.submit(ch, d)` | 要留下來的結果，例如集章、下注、答案。送出不排鎖，斷網時先存在手機、之後補送，回傳 `{ id, sigOk }` |
| `host.inbox(ch, since)` | 讀送出的結果。工作人員讀全部；學員只讀自己的，小隊頻道讀得到同小隊的 |
| `host.sign(text, squad)` | 工作人員產生關主密鑰，綁定小隊（`'*'` 表示不限小隊）。學員送出 `{ signed, sig }` 時由伺服器驗證 |
| `host.score({ stage, stageName, team, score })` | 關主端用：這一隊過了這一關，分數送進「團隊計分」。每個活動自動有一個 Game（名稱就是活動名稱，立即發布），每隊每關一筆，同一關重送是更新、不會重複加。只有工作人員可以用，要從活動進來 |
| `host.load(k)`、`host.save(k, v)` | 存在這支手機、這個人、這個活動的存檔 |
| `host.qr(el, text)`、`host.link(params)` | 畫 QR code；產生這個遊戲頁的網址 |
| `host.scan(title)` | 在遊戲裡開相機掃 QR code，回傳掃到的文字（取消是 null）。學員不要用手機相機 App 掃：相機 App 會用別的瀏覽器打開，又要重新登入 |
| `host.h`、`host.toast`、`host.modal`、`host.fail` | 畫面小工具（和 App 同一套） |

頻道範圍由伺服器檢查，學員改前端也繞不過：

| 頻道開頭 | 誰可以用 |
| --- | --- |
| `sq3…` | 只有第 3 小隊（和工作人員） |
| `w-…` | 只有工作人員 |
| `in-…` | 學員只能送，看不到別人送的（例如下注） |

## 寫遊戲的原則（約 100 人同時玩）

- **能在手機算的就在手機算**：地圖、倒數、特效、題目判斷、進度顯示都在手機上做。
- **即時同步只放可以重算的狀態**：Google 快取可能被清掉。
- **一定要留下的東西用 `host.submit`**：每個動作送一次就好，不要每秒都送。
- **分數由關主端上傳**：用 `host.score`，每過一關送一次，不要讓學員端自己加分。
